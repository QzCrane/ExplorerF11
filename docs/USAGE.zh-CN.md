# 使用说明

怎么运行 ExplorerF11、怎么读它给出的报告。Win32 层面的行为见
[ARCHITECTURE.md](ARCHITECTURE.md)，残留项完整清单见 [RESIDUE.md](RESIDUE.md)。
English: [USAGE.en.md](USAGE.en.md)。

## 它做什么

资源管理器打开文件夹窗口、从最小化还原，或者你新建选项卡时，工具会向那个窗口投递一次
F11 往返：进全屏，再退出来。这个过程会重建资源管理器的 XAML 命令栏，重建后的窗口翻目录
更快。之后打开的窗口也会自动处理；已经开着的窗口除非你手动应用，否则不动。

计数单位是**窗口**，不是选项卡。F11 由窗口框架处理，一次往返覆盖该窗口的所有选项卡，
它们共享同一个加速状态。选项卡没有独立的 F11 状态，不会被单独加速。状态行里的
`已加速 1 个窗口（含 2 个选项卡）`，括号里只是这些窗口当前装了多少选项卡，不是另一份
工作量统计。

跨进程动作只有 `PostMessageW`：不注入、不模拟真实按键、不改资源管理器的界面、不联网。
它以当前用户身份运行，可以和 ExplorerPatcher、StartAllBack 共存。这是把手动技巧自动化，
不是微软的修复，也不会改动你的文件夹选项和视图设置。

## 运行

双击 `ExplorerF11.exe`，托盘出现图标。打开一个文件夹窗口，悬浮提示会从「运行中，等待
文件夹窗口」变成窗口计数。exe 放哪都行，但别放在会被自动清理的目录；勾选自启之后挪动
位置，需要重新勾一次。

托盘 →「开机自启」只写入一条
`HKCU\Software\Microsoft\Windows\CurrentVersion\Run\ExplorerF11`，内容是带引号的 exe
完整路径，不带参数。勾选状态反映的是开机时到底会不会启动：如果你在任务管理器里禁用过，
在这里重新勾选会同时清掉 Windows 的 `StartupApproved` 禁用标记。

退出用托盘 →「退出」。彻底卸载先执行 `ExplorerF11.exe --clean`，再删掉 exe，见
[卸载](#卸载)。

## 托盘菜单

点击托盘图标（左右键均可）打开菜单，它由 `BuildTrayMenu()` 即时构建，固定五段：

```
ExplorerF11 1.0.5  ·  已加速 3 个窗口（含 5 个选项卡）   ← 灰色，不可点
────────────────────────────
对所有已打开的窗口应用
对当前窗口立即应用
暂停加速
────────────────────────────
✓ 新建选项卡时重新加速窗口
✓ 启动时加速已打开的窗口
✓ 开机自启
界面语言  ▸  简体中文 / 繁體中文 / English / 日本語 / 한국어
────────────────────────────
残留报告（2 项）…
────────────────────────────
退出
```

| 项 | 行为 |
|---|---|
| 状态行 | 版本号，加上「运行中，等待文件夹窗口 / 已加速 N 个窗口（含 M 个选项卡）/ 已暂停加速」之一。报问题时也能一眼看出是哪个版本 |
| 对所有已打开的窗口应用 | 对所有文件夹窗口强制重做一次，包括已标记的。换主题或改缩放之后用 |
| 对当前窗口立即应用 | 只作用于你最后用的那个文件夹窗口；没有窗口时变灰 |
| 暂停 / 恢复加速 | 临时停手，比如连续开十几个窗口时。不记住，重启后恢复运行状态 |
| 新建选项卡时重新加速窗口 | 默认开。按 `+` 时对**所在窗口**重做，不是只对那个选项卡。关掉可避免整窗闪一下 |
| 启动时加速已打开的窗口 | 默认开。关掉后只处理启动之后新建的窗口 |
| 开机自启 | 见[运行](#运行) |
| 界面语言 | 五项单选，立即生效并记住 |
| 残留报告 | 打开只读清单。唯一的删除动作在窗口内的「清理残留…」按钮 |

删除动作放在报告窗口里，而不是托盘菜单里，这样它前面总是先列出要删什么。按钮名带
`…`，点击后会再确认一次。

## 残留报告

「残留报告（N 项）…」打开的内容和 `--status` 打印的完全一样。开头说明数据来源：

```
ExplorerF11 1.0.5 · 残留报告
程序：D:\Tools\ExplorerF11.exe
时间：2026-11-15 11:20:31（本机时间） · 界面语言：简体中文
范围：11 个可能位置，分 3 组；逐项列出检查结果，不存在的位置同样列示。
================================================================

结论：共 2 项需要清理，合计 372 B。
      本程序 1 项（164 B）；Windows 自动记录 1 项（208 B）。
      标注「可清理」的项目会被窗口里的「清理残留…」删除；程序本体不删除。
```

接着是三组：本程序写入、Windows 自动记录、程序文件。每项四行：

```
[2] 开机自启项 · 存在 · 可清理
      谁写：本程序；你在托盘菜单里勾选「开机自启」时
      位置：HKCU\Software\Microsoft\Windows\CurrentVersion\Run\ExplorerF11
      内容："D:\Tools\ExplorerF11.exe" (164 B)
      说明：一个 REG_SZ 值：带引号的 exe 完整路径，不带任何参数。取消勾选即删除
```

- **谁写**：写入方，以及触发它的条件；
- **位置**：完整路径，带 `HKCU\` 前缀，可以直接粘进 regedit 的地址栏；
- **内容**：当前值；项目不存在时省略这一行；
- **说明**：这项是什么、清理时删不删、Windows 会不会再建回来。

不存在的位置也照列，标「不存在」。只列存在项的报告没法证明别处是干净的。

底部三个按钮：**复制全部 / 清理残留… / 关闭**。

- 「清理残留…」是全程序唯一的删除入口。它先逐类列出要删的内容并询问；选「否」什么
  都不动。确认后报告当场刷新，程序继续运行，你可以接着核对结果。
- 报告开着的时候会自己更新：新开或关闭文件夹窗口、暂停或恢复、改设置、切语言，正文
  都会重建，滚动位置保持不变。
- 标题栏、任务栏和 Alt+Tab 用程序自己的图标。托盘图标运行时是蓝色闪电，暂停后变灰，
  悬停显示当前状态和窗口数。

## 命令行

| 参数 | 作用 | 写不写 |
|---|---|---|
| 无参数 | 在托盘里运行 | 默认不写 |
| `--install` | 在托盘里运行，并勾选开机自启 | 写一条 Run 值 |
| `--uninstall` | 只删除开机自启项 | 删一条 Run 值 |
| `--status` | 打印完整报告；退出码 0=干净、1=有可清理残留 | 只读 |
| `--clean` / `--purge` | 关掉正在运行的实例，删除全部可清理残留后退出 | 删 |
| `--menu` | 把托盘菜单按文本打印出来（供测试与排查） | 只读 |
| `--lang <tag>` | 本次运行的界面语言：`zh` / `zh-Hant` / `en` / `ja` / `ko` | 只读 |
| `--log` | 写日志到 `%TEMP%\ExplorerF11.log` | 建一个文件 |
| `--no-initial` | 不处理启动前已经打开的窗口（仅本次） | 只读 |
| `--quiet` | 不弹对话框（脚本用） | 只读 |
| `--help` / `-h` / `/?` | 打印帮助 | 只读 |
| `--version` / `-v` | 打印版本号 | 只读 |

`--lang=<tag>` 与 `--lang <tag>` 都接受。

```powershell
ExplorerF11.exe --status --quiet
if ($LASTEXITCODE -eq 0) { "干净" } else { "有残留" }
```

| 退出码 | 含义 |
|---|---|
| 0 | 请求的动作成功；对 `--status` 来说就是机器干净 |
| 1 | `--status` 找到可清理残留 |
| 2 | 用法错误：未知选项、`--lang` 缺值，或不支持的语言标签 |

用法错误会把出错的参数原样打印并指向 `--help`。未知选项一律不忽略：
`ExplorerF11.exe --cleen` 不允许变成一个看起来「做了点什么」的托盘实例。裸写 `--lang`
会给出专门的「缺少语言标签」提示；`--lang --quiet` 报缺值，而不是把 `--quiet` 当语言标签。

## 界面语言

四种来源，优先级从高到低：

1. `--lang <tag>`（仅本次运行）；
2. `EXPLORERF11_LANG=<tag>`（仅本次运行，适合便携拷贝和脚本）；
3. 托盘 →「界面语言」里的选择，供后续启动使用；
4. 系统语言：先看区域格式，再看界面语言。

可接受标签为 `zh`、`zh-Hant`、`en`、`ja`、`ko`；`zh-tw`、`zh-cn`、`ja-jp`、
`ko-kr` 等区域别名会归一到这五种。前两种是「这一次照做」的指令，压过保存的选择；
保存的选择压过系统语言，这样托盘点一下才能在重启后仍然有效。

`HKCU\Software\ExplorerF11\Language` 只在所选语言与系统语言不同时存在。选回系统语言
即删除该值，键空了连键一起删。从不打开子菜单的用户一个字节都不写。界面语言只影响文字，
不影响任何行为。

## 设置项

三项，前两项默认开：

| 设置 | 默认 | 存哪 |
|---|---|---|
| 新建选项卡时重新加速窗口 | 开 | `HKCU\Software\ExplorerF11\Tabs`（只在关闭时存在） |
| 启动时加速已打开的窗口 | 开 | 同上 `InitialSweep` |
| 界面语言 | 跟随系统 | 同上 `Language`（只在偏离系统语言时存在） |

改回默认会立即删掉那个值，键空了连键一起删。在注册表里，「恢复默认」和「从未安装」
是同一种状态。

## 常见问题

**窗口开了但没变快？**
先看状态行是不是「已暂停加速」。然后用「对所有已打开的窗口应用」手动重做一遍——这能
区分「钩子没触发」和「触发了但没效果」。如果强制重做也没用，说明这个 Windows 版本的
行为变了。用 `--log` 启动后查 `accelerated:` 行，可以确认消息到底有没有投递出去。

**新建的选项卡没吃到？**
检查「新建选项卡时重新加速窗口」是否还勾着。勾着却不动，多半是这个窗口在启动时被
跳过了（工具启动前就开着，又关掉了启动清扫）。手动应用一次即可。

**按 `+` 时整窗闪一下？**
那是全屏切换变得可见了。关掉「新建选项卡时重新加速窗口」可消除闪烁；窗口本身仍然
是加速过的，只是新选项卡不再触发重做。

**界面语言在哪切？**
托盘 →「界面语言」。五个选项各用自己的文字写（简体中文 / 繁體中文 / English /
日本語 / 한국어），所以切到看不懂的语言也能找回来。切换立即生效，不用重启。

**切了语言为什么菜单没变？**
检查是不是带着 `--lang` 启动、或者设了 `EXPLORERF11_LANG`——这两种是一次性指令，
优先级高于托盘里的选择。清掉之后托盘选择才会生效。

**装了 ExplorerPatcher / StartAllBack 冲突吗？**
不冲突。它只投递消息，不碰界面。实测环境就装着 ExplorerPatcher。

**重启资源管理器之后失效？**
它监听 `TaskbarCreated`，重新注册 Shell 钩子并重建托盘图标；重注册失败会用原命令行
重启自己。如果图标还在但点了没反应，说明这条路径出了问题，请带上日志反馈。

**多显示器 / 高 DPI？**
全屏切换只发生在目标窗口所在的显示器上，不会移动其他窗口。界面按系统 DPI 缩放。

## 卸载

```powershell
ExplorerF11.exe --clean     # 关掉正在运行的实例，清理本程序写入和 Windows 记录的部分
Remove-Item .\ExplorerF11.exe
```

`--clean` 会清掉设置（含语言）、自启、日志，以及 Windows 为这个 exe 建的记录：托盘
图标缓存、启动开关、兼容性存储、MuiCache、UserAssist，以及有权限时的 Prefetch。它会
逐类打印清理结果；某类没出现在结果里，说明本来就没有。

`%WINDIR%\Prefetch` 只有管理员能读写，不带提权时这些条目会保留，报告也会如实说明。
其余位置见 [RESIDUE.md](RESIDUE.md)；`--status` 是程序对自己状态的交代。
