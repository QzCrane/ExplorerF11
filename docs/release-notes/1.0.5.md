# ExplorerF11 {{version}}

A patch release for one defect: **the count of accelerated windows only ever went
up.** Closing a folder window left the tray tooltip, the menu header and an open
residue report showing the old number until some later event happened to refresh
them. Nothing else about the program changed.

The executable is {{bytes_grouped}} bytes ({{kib}} KiB). It is **unsigned**, so
SmartScreen will warn on first run; the SHA-256 below is the integrity check that
replaces a signature.

## What you get

One 64-bit Windows executable — no installer, no runtime, no external files.
Put `{{asset}}` anywhere and run it. Built with MinGW-w64 GCC 16.1.0 through
`make -B` on the release machine; MSVC builds the same sources in CI with
`/std:c++latest`.

## Fixed

When a window closes, the shell reports `HSHELL_WINDOWDESTROYED` **while the
window still exists and still carries the mark** — measured: `IsWindow` and
`IsMarked` both true, the properties gone about 50 ms later. The handler rebuilt
the tray and the report at that instant, so the read still counted the dying
window. Worse, the report's refresh is posted with the snapshot taken at that
instant, so nothing read the desktop again: the number stayed wrong until an
unrelated event forced a rebuild.

The rebuild now waits for a 60 ms one-shot timer. By the time it runs, `IsWindow`
says the window is gone and the maintained set drops the entry. A burst of closes
collapses into that one timer, so closing ten windows still costs one rebuild.

The old source-contract test for this passed the whole time: it asserted that the
line `IsMarked(gone)) OnStateChanged();` existed, which it did. The line was
right and the moment was wrong.

## Tests

The defect was found by removing tests of exactly that kind. About fifty
assertions in `test_robustness.py` and `test_icons.py` matched source lines
instead of observing behaviour; they went red on renames that preserved
behaviour and green on dead code. Every guarantee with an outside observer now
uses one:

- `test_smoke.py` opens and closes real windows and reads the report the program
  drew — the start-up sweep and `--no-initial`, the count following a close, and
  the tray surviving a `TaskbarCreated` broadcast (same pid, hook re-registered,
  events still arriving). It asks the report window for its icons with
  `WM_GETICON` instead of grepping `WM_SETICON`.
- `test_residue_report.py` plants a UserAssist entry whose value name is
  `ROT13(path)`, the way Windows stores it, and requires the report to count
  exactly one more entry. A wrong rotation reads "clean" on a machine that has
  launched the exe hundreds of times.
- What remains in `test_robustness.py` is marked `WHITE-BOX`: one assertion per
  defect with no outside trigger (a registration failure that no supported API
  can provoke, an IPC count the shell does not expose), each naming the
  observation that is missing. They assert a property — a call-site count, a
  forbidden pattern, an ordering between a check and the action it guards — never
  a formatted line.

Each new assertion was verified by putting the defect back: reverting the timer,
ignoring `--no-initial`, dropping the tick comparison, removing the memoised
early return and adding a second `PROP_MARK` writer all go red.

{{gates}} gates, **{{assertions}} assertions**, all green on this exact source
tree. The extra time over 1.0.4 goes into the observations above; wall-clock
duration varies with the machine and is not a correctness claim.

## Verify before running

```
{{sha256}}  {{asset}}
```

`SHA256SUMS.txt` is attached. GNU `sha256sum` prescribes the line format
(`digest`, separator space, text/binary mode flag, filename), not the filename of
the manifest itself; `sha256sum -c SHA256SUMS.txt` works, and the digest is paired
with the asset name in the file content. On Windows:

```powershell
Get-FileHash .\{{asset}} -Algorithm SHA256
(Get-Item .\{{asset}}).VersionInfo.FileVersion   # {{version}}.0
.\{{asset}} --version                            # ExplorerF11 {{version}}
```

## Residue policy

The report lists only ExplorerF11's own registry and tray records. `--clean` asks
for confirmation and deletes those records and nothing else. The default
configuration writes nothing, and this release added no cache, no file and no
registry value.
